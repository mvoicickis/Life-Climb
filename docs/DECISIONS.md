# Product Decisions

Irreversible (or locked) product decisions for LifePoints.
Keep this file short. Debate once. Record. Move on.

Constitutions explain why. This file only records what is settled.

---

## Accepted

- One Battle Plan per day.
- Multiple Battles inside one Battle Plan.
- One Mountain per player.
- Many Destinations on that Mountain; focus selects the active Destination.
- Destination is subtle utility on Mountain (not the home-screen hero).
- Mission is player-facing terminology (not “Plan” on the critical path).
- Journey is history (progress ledger)—not the Mountain world.
- Character (You) is identity and account—not a planning surface.
- Mountain is the world.
- Today is the primary daily experience.
- Mission is entered from Mountain.
- Every Mission serves a Destination; every Battle belongs to a Mission.
- No permanent new product areas without Feature Framework approval.
- Prefer improving an existing screen over adding a new one.
- Daily loop outranks epic loop for shipping priority.
- Destination states: Active, Completed, Deleted (no Paused).
- Engineering names may differ from player names; change copy first, not schema.

## Rejected

- One Fight Law (one Battle only per day).
- Multiple daily plans.
- Dashboard home (productivity dashboard as the product center).
- Inbox-first Today.
- Project-management terminology as player language.
- Separate Planning screen as a permanent peer surface.
- Calendar-first workflow.
- Habit-tracker / notes-app / knowledge-base as the product identity.
- New permanent product areas invented mid-implementation.
- Paused Destination state.
- Journey or Character as daily home / fight surface.

---

## How to use

1. Before proposing a product change, read Accepted + Rejected.
2. If it conflicts → stop; do not implement.
3. To reverse a decision → edit this file in the same PR that implements the reversal, with a one-line reason.
